# Independently verify shared watcher lifetime and advisory delivery

- Task ID: `TASK-002`
- Tier: `review`
- Logical role hint: `review`
- Dependencies: `TASK-001`

## Authorized requirements
- `REQ-001` — A workflow/orchestrator registry must have at most one host-owned active watcher that replays events for all registered child Agent Runs. Completion of any child cannot stop it; it exits only through the existing host SIGTERM/SIGINT or bounded-cycle stop behavior.
- `REQ-002` — Only after replay durably imports an eligible child event and advances its source cursor, the watcher must best-effort invoke the configured host notification/wake adapter with the NOTIFY-001 record. The record excludes arbitrary child payloads and its summary is at most 512 Unicode characters.
- `REQ-003` — Notification or wake delivery is advisory and at-least-once: adapter failure, absence, or duplicate delivery cannot alter lifecycle authority, stop the watcher, or remove the already-imported durable inbox event. Consumers deduplicate advisory delivery by event_id; the host can recover the event from the durable inbox after restart.

## Acceptance
- `AC-001` — Register child A and child B in one registry; run one watcher; complete A; observe that the watcher remains active; then import B. A competing watcher is rejected by the single-writer lease and no child completion invokes shutdown.
- `AC-002` — An eligible imported event invokes the adapter only after it appears in the durable inbox and cursor state is advanced. The record contains only NOTIFY-001 fields, preserves event_id, excludes arbitrary payload content, and bounds summary to 512 Unicode characters.
- `AC-003` — An adapter failure and a duplicate event_id leave the watcher active and the imported inbox record readable. After restart, the host can recover the same event from the durable inbox without any notification-driven lifecycle mutation.
