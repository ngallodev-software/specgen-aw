SpecGen

Working project name. Final product/repository naming is intentionally undecided.

SpecGen is an independent specification authoring and compilation system intended to turn ambiguous product or engineering intent into a versioned, machine-readable specification with traceable human-readable projections, evaluation intent, and optional execution-target artifacts.

The project is Agent-Workflow-aware but not Agent-Workflow-dependent. Its canonical specification model belongs to SpecGen. Agent-Workflow is one compilation target whose supported contract versions are declared and tested explicitly.

Current version

  • Project: 0.1.0
  • Canonical spec schema: specgen/spec/v1alpha1
  • Initial Agent-Workflow compatibility target: 0.9.0

See compat/agent-workflow/COMPATIBILITY.md for the exact schema IDs currently recognized.

Architecture in one sentence

SpecGen owns specification meaning; target adapters lower a validated canonical specification into external formats without giving those targets authority over the canonical model.

Repository map

  • schemas/ — SpecGen-owned versioned machine-readable contracts.
  • compat/ — snapshots/manifests used to verify compatibility with external targets; never runtime authority.
  • docs/ARCHITECTURE.md — current system architecture.
  • docs/DESIGN_PRINCIPLES.md — design laws and boundaries.
  • docs/ROADMAP.md — mutable implementation roadmap.
  • docs/adr/ — architecture decision records; accepted decisions are append-only except for status/supersession metadata.
  • docs/research/ — prior-art assessments and source review notes.
  • src/specgen/ — minimal package scaffold.

Minimal CLI

The initial package deliberately does almost nothing beyond exposing its own version and declared compatibility data:

python -m specgen version
python -m specgen compatibility

The CLI is a seam for future validators, renderers, elicitation workflows, and target compilers; those are roadmap work, not silently implied by the scaffold.
